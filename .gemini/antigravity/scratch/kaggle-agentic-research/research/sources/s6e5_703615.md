In previous comps, I tried doing some feature/model selection, but then after the comp ended, I observed that the logistic regression with everything did better.

For diversity, I just use my intuition / common sense not to add too similar models. I make sure each model is different. So I don't change the seeds and submit two of the same models with different seeds. Also i don't just remove 1 feature or add 1 feature. I make sure each model is really different somehow and then I just add to logistic regression. 

I am also very careful to make sure all models are leak free. So for example, I always add nested fold safe TE. And if i stack model, I will use nested 5 fold for level 1 to feed into level 2. Then level 2 is leak free and i can put it in logistic regression.

### Comment #21 by Author (2026-06-02 16:40:50.340000) [Votes: 1]

In every playground, our models are learning two sources of signal (i.e. two ways to use features to predict target). Kaggle playground competitions `train.csv` is synthetic data that is generated by starting with an original dataset (let's call it `original.csv`). The synthetic data generation process preserves the signal in `original.csv` and adds the same artifact signal every month.

The artifact feature engineering (i.e. feature to extract the artifact signal) has basically been all discovered already. Just read old playground solutions. We target encode the numerical features. We `original.groupby(COL)[TARGET].mean()` and then merge this to `train.csv`. We extract the digits etc etc. These are all known and my LLM Agents know them all because i tell my agents to read my past solutions to learn them.

What is new every month is the signal from `original.csv`. Some months the dataset `original.csv` is literally random numbers with zero signal. Some months the `original.csv` is a formula that we 100% discover. Some months the `original.csv` is a very simple relationship between features and target that logistic regression can learn or XGB with max_depth=1 can learn. All of these cases are basically nothing for us to discover.

This month was different. The `original.csv` dataset has real signal that wasn't trivial nor completely discovered. If we train XGB on `original.csv` by itself, then XGB needed max_depth large (like 6 or 8 i forget). This means there are real patterns and real feature interactions and real complicated relationships between target and features for us to discover. To extract this signal, we need to feature engineer like typical (real life) tabular data competitions. We need to multiply columns together, we need to transform columns, we need to make special deep learning (NN) model architectures. There is actually something for us to do.

When `original.csv` has no signal. Then Codex can find the optimal solution by just extacting the artifact signal in like 1 or 2 days.
